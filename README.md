# dev-lab

Бэкенд на Go: сервис, который последовательно усложняется, и замеры на каждом шаге.

Репозиторий держится в одном формате: каждое изменение, которое должно было
что-то улучшить, сопровождается **числом до и после**. Замер без методики и
окружения сюда не попадает.

## Структура

| Директория | Что внутри |
|---|---|
| [`service/`](service/) | Основной сервис. Растёт от `net/http` без фреймворка до отказоустойчивого в Kubernetes |
| [`cli/`](cli/) | CLI-утилита на стандартной библиотеке |
| [`benchmarks/`](benchmarks/) | Замеры: вопрос → окружение → методика → цифры → вывод |

## Принципы

- **Стандартная библиотека, пока её хватает.** Фреймворк берётся тогда, когда
  понятно, что именно он прячет, а не вместо этого понимания.
- **Число важнее галочки.** «Добавил очередь» — не результат. «Вынес отправку
  в очередь, p99 упал с 1.8 с до 40 мс, при недоступности SMTP теряется
  0 сообщений вместо всех» — результат.
- **Отрицательный результат публикуется.** Оптимизация, которая не дала
  выигрыша, с объяснением почему — такой же валидный замер.
